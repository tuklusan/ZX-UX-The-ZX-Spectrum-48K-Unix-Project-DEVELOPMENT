# ZX-UX rbc fresh-chat handover — 2026-10-22

## Goal
Develop `rbc`, a Python Sinclair BASIC-to-ZX-UX SSX1 command-line compiler
based on Melissa O'Neill's `pyhsb` implementation of HiSoft BASIC v1.1.
Embed the 768-byte VGA 8x8 `font32` and 21 process-local UDG glyphs.
The primary visual and control goals are faithful Galaxians and Invaders,
then the other 58 historical BASIC programs. Avoid re-writing the games into C48.

## Tested, and limits
- Real ZX-UX kernel ran genuine HiSoft `PRINT "HELLO"`, emitted `HELLO`,
  and exited with status zero. The generated code includes VGA font setup.
- Current `rbc` source path builds `inkey-poll.bas` into a 1,562-byte SSX1.
  Regeneration reproduced saved `inkey.ssx` byte-for-byte.
  The ZX-UX kernel exits with status zero on the delayed `z` key test.
  `INKEY$` is immediate, unbuffered keyboard state, never terminal input.
- Static memory checks: 16 test cases pass. Strict mode blocks risky
  `POKE`, `PEEK`, numeric `USR`, `RANDOMIZE USR`, `CLEAR`, and unsupported
  memory/I/O use. `--memory-policy review` is only for isolated trials.
- `rbc` sets `CHARS` (0x5C36) to the embedded VGA 8x8 font table and sets
  `UDG` (0x5C7B) to process-local glyph storage. Both are restored on
  ordinary return. More work is needed for early exits and interruptions.
- `rbc` compiles at three different addresses to infer relocation sites.
  All changed bytes must be explained by address shifts. This alone does
  not guarantee ZX-UX compatibility for every ROM call.
- Galaxians' HiSoft-generated code has displayed its recognizable original
  opening instruction screen under ZX-UX; correct game play is not proven.
- Invaders executes under ZX-UX but screen contents are still damaged.
  Neither game is yet faithful enough to declare complete.
- Latest GitHub Actions 60-program sweep completed in run `39870573164`.
  Exactly 7 of 121 tested inputs passed the compilation stage: `HELLO`,
  and six source tape variants for programs 07, 23, 25, 39, 50, and 53.
  The workflow was green because it collected failures rather than requiring
  every compilation to pass. Do not report 121 successful compilations.
  The other failures include Python exceptions, text input tokenization,
  compiler limitations, and missing BASIC line targets. The full JSON is
  in `runner-sweep/rbc-60-results.json`.
- Original BASIC corpus scan: 59 of 60 source tapes were readable using
  the generic tape parser; 52 had statements blocked by strict policy.
  The screen is conservative and includes cases still needing analysis.
- Earlier scratch source tests and the local regression suite passed:
  font differs from ROM 8x8, Galaxians/Invaders SSX1 relocation layout,
  HELLO on real ZX-UX kernel, and genuine v1.1 TZX-to-TAP extraction.

## Rebuild example
After cloning live GitHub main to an isolated checkout, extract the new
checkpoint ZIP outside the checkout, then fetch upstream:
`git clone https://github.com/imneme/pyhsb pyhsb`
`git -C pyhsb checkout --detach 7cc87dafb58fcf5632b7190320dd11c30b4fe961`
The file `scratch/rbc/rbc.py` accepts:
`python scratch/rbc/rbc.py PROGRAM.bas --frontend pyhsb --sdk SDKDIR --rom SDKDIR/rom/48.rom --tape HISOFT_V11_SIDE_A.tzx -o PROGRAM.ssx --report PROGRAM.json`
Use `--memory-policy review` only when investigating a flagged program
in an isolated emulator. Keep the warnings with any generated output.
